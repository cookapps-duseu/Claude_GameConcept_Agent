# concept-clarifier 스킬

사용자가 게임 컨셉 생성을 요청하면 이 스킬을 실행한다.

**트리거 예시**: "게임 컨셉 만들어줘", "게임 기획 도와줘", "컨셉안 생성해줘", "게임 아이디어 구체화해줘"

> **핵심 원칙**: 이 스킬은 **멀티턴 대화**다. 각 Phase는 반드시 사용자의 응답을 받은 뒤에만 다음 Phase로 넘어간다. Phase A~F는 절대 한 응답 안에서 연달아 처리하지 않는다.

---

## 시작 전 — TodoWrite 초기화

스킬을 시작하기 전에 반드시 TodoWrite로 전체 진행 목록을 생성한다:

```
TodoWrite([
  { content: "장르/타겟 대화",              activeForm: "장르/타겟 파악 중",            status: "in_progress" },
  { content: "기본 항목 파악",              activeForm: "기본 항목 파악 중",            status: "pending" },
  { content: "코어 루프 · 핵심 요소 파악",  activeForm: "코어 루프 · 핵심 요소 파악 중", status: "pending" },
  { content: "전체 항목 확인",              activeForm: "전체 항목 확인 중",            status: "pending" },
  { content: "최종 컨셉 확인",             activeForm: "최종 컨셉 확인 중",            status: "pending" },
  { content: "컨셉안 생성 (하네스)",        activeForm: "컨셉안 생성 중 (하네스)",       status: "pending" },
])
```

---

## Phase A — 장르/타겟 대화

게임 기획 컨설턴트 역할로 자연스럽게 질문한다.
이미 사용자가 언급한 정보는 다시 묻지 않는다.

수집 항목:
- `genre`: 장르와 핵심 컨셉 (필수)
- `target_user`: 타겟 유저 (선택 — 사용자가 "없음" / "모름"으로 답해도 완료)

**⛔ STOP: Phase A 질문을 보낸 뒤 반드시 멈춘다. 사용자 응답이 오기 전까지 Phase B로 넘어가지 않는다.**

사용자가 답변하면:
- `genre`와 `target_user` 모두 파악됐으면 → "장르/타겟 대화"를 `completed`로 표시하고 Phase B를 진행한다
- 아직 필요한 정보가 부족하면 → Phase A 질문을 이어간다

---

## Phase B — 기본 항목 파악

TodoWrite로 "기본 항목 파악"을 `in_progress`로 업데이트한다.

Phase A에서 파악한 장르/타겟을 바탕으로 아래 항목들을 **자연스러운 대화**로 물어본다.
모든 항목을 한꺼번에 리스트로 나열하지 말고, 자연스럽게 이어지는 질문으로 물어본다.
이미 사용자가 언급한 항목은 건너뛴다.

수집 항목:
- `platform`: 플랫폼 (모바일, PC, 콘솔 등. 미지정 가능)
- `dimension`: 그래픽 방향 (2D, 3D, 픽셀아트 등. 미지정 가능)
- `reference_games`: 레퍼런스 게임 목록 (없으면 [])
- `play_mode`: 플레이 방식 (싱글, 멀티, 협동 등. 미지정 가능)
- `combat_mode`: 전투/대결 방식 (실시간, 턴제, 전략 등. 미지정 가능)
- `keywords`: 핵심 키워드 목록 (분위기, 테마 등. 없으면 [])

질문 예시 (장르에 맞게 자연스럽게 변형):
- "어떤 플랫폼을 생각하고 계신가요?"
- "그래픽 스타일은 어떻게 가져가고 싶으신지요? 2D, 3D, 픽셀아트 같은 방향이 있으신가요?"
- "참고하고 싶은 레퍼런스 게임이 있으신가요?"
- "싱글플레이 위주인가요, 멀티나 협동 요소도 생각하고 계신가요?"
- "전투나 대결 방식은 어떻게 생각하고 계신가요?"
- "게임의 분위기나 테마를 키워드로 표현한다면 어떻게 될까요?"

**⛔ STOP: 위 질문들을 보낸 뒤 반드시 멈춘다. 사용자 응답이 오기 전까지 Phase C로 넘어가지 않는다.**

사용자가 답변하면:
- 모든 항목이 확인됐거나 사용자가 "모른다" / "없다"고 한 항목은 null / []로 처리
- 확인 안 된 항목이 있으면 → 해당 항목만 추가 질문하고 다시 멈춘다
- 모두 확인됐으면 → "기본 항목 파악"을 `completed`로 표시하고 Phase C로 진행

---

## Phase C — 코어 루프 · 핵심 요소 심층 파악

TodoWrite로 "코어 루프 · 핵심 요소 파악"을 `in_progress`로 업데이트한다.

Phase A, B에서 파악한 정보를 바탕으로 아래 항목들을 **자연스러운 대화**로 물어본다.
장르와 레퍼런스에 맞춘 구체적인 예시를 들어가며 질문한다.

수집 항목:
- `core_loop`: 원하는 게임 코어 루프 (한 사이클 흐름. 없으면 null)
- `key_elements`: 게임에 꼭 있었으면 하는 핵심 요소 목록 (없으면 [])
- `must_have_elements`: 인게임에 반드시 들어가야 할 요소 목록 (없으면 [])

질문 예시 (장르와 앞서 나온 정보에 맞게 변형):
- 코어 루프: "한 판이나 한 사이클이 어떻게 흘러갔으면 하시나요? 예를 들어 '탐험 → 전투 → 보상 수집 → 강화' 같은 흐름이 있으신가요?"
- 핵심 요소: "게임에 꼭 있었으면 하는 시스템이나 콘텐츠가 있으신가요? 덱빌딩, 아이템 강화, 소셜 기능, 시즌 패스 같은 것들이요."
- 필수 요소: "반드시 인게임에 포함돼야 한다고 생각하시는 요소가 있으신가요? 절대 빠지면 안 되는 것들이요."

모든 항목을 한꺼번에 물어봐도 되고, 한두 개씩 나눠서 물어봐도 된다.
사용자가 "없다" / "모르겠다"고 한 항목은 null / []로 처리한다.

**⛔ STOP: 위 질문들을 보낸 뒤 반드시 멈춘다. 사용자 응답이 오기 전까지 Phase D로 넘어가지 않는다.**

사용자가 답변하면:
- 세 항목이 모두 확인됐으면 → "코어 루프 · 핵심 요소 파악"을 `completed`로 표시하고 Phase D로 진행한다
- 아직 확인 안 된 항목이 있으면 → 해당 항목만 추가로 질문하고 다시 멈춘다

---

## Phase D — 전체 항목 확인

TodoWrite로 "전체 항목 확인"을 `in_progress`로 업데이트한다.

지금까지 수집한 모든 값을 채워 아래 폼을 표시한다.
수정할 항목을 알려달라고 안내하고, 없으면 그대로 진행한다고 안내한다.

```
[컨셉 세부 사항] 아래 내용을 확인해 주세요. 수정할 항목이 있으면 말씀해 주세요.

플랫폼: {platform 또는 미지정}
그래픽: {dimension 또는 미지정}
레퍼런스 게임: {쉼표 구분 목록 또는 없음}
플레이 방식: {play_mode 또는 미지정}
전투/대결 방식: {combat_mode 또는 미지정}
키워드: {쉼표 구분 목록 또는 없음}
코어 루프: {core_loop 또는 미지정}
핵심 요소: {쉼표 구분 목록 또는 없음}
필수 인게임 요소: {쉼표 구분 목록 또는 없음}
추가 설명: {free_text 또는 없음}

수정할 내용이 없으면 "확인" 또는 "다음"이라고 말씀해 주세요.
```

**⛔ STOP: 위 폼을 표시한 뒤 반드시 멈춘다. 사용자 응답이 오기 전까지 Phase E로 넘어가지 않는다.**

사용자가 답변하면:
- 수정 요청이 있으면 → 해당 항목 업데이트 후 폼을 다시 표시하고 다시 멈춘다
- 확인/다음/없음 등 완료 응답이면 → "전체 항목 확인"을 `completed`로 표시하고 Phase E로 진행한다

---

## Phase E — 최종 확인

TodoWrite로 "최종 컨셉 확인"을 `in_progress`로 업데이트한다.

**Phase E 시작 시 `free_text`를 먼저 작성한다.**

지금까지 나눈 대화 전체를 바탕으로 `free_text` 서술형 요약문을 작성한다.
파이프라인 에이전트가 컨셉을 충분히 이해할 수 있도록 아래 항목을 모두 포함한다:
- 게임의 전체 개념과 방향
- 코어 루프의 구체적인 흐름 (단계별)
- 각 핵심 요소가 게임플레이에서 어떻게 작동하는지
- 필수 인게임 요소가 왜 중요한지, 어떻게 활용되는지
- 레퍼런스 게임과의 관계 및 차별점 (레퍼런스가 있는 경우)
- 플레이어가 반복적으로 플레이하게 되는 동기 (재미 구조)

`free_text`는 짧은 키워드 나열이 아니라 **서술형 문단**으로 작성한다. 최소 200자 이상.

작성한 `free_text`를 포함해 수집된 **12개 전체 필드**를 요약 표시한다:

```
[최종 확인] 아래 내용으로 게임 컨셉안을 생성합니다.

- 장르/컨셉: <genre>
- 타겟 유저: <target_user 또는 미지정>
- 플랫폼: <platform 또는 미지정>
- 그래픽: <dimension 또는 미지정>
- 레퍼런스 게임: <목록 또는 없음>
- 플레이 방식: <play_mode 또는 미지정>
- 전투/대결 방식: <combat_mode 또는 미지정>
- 키워드: <목록 또는 없음>
- 코어 루프: <core_loop 또는 없음>
- 핵심 요소: <목록 또는 없음>
- 필수 인게임 요소: <목록 또는 없음>

[대화 내용 요약 (추가 설명)]
<free_text — 위에서 작성한 서술형 요약문 전체>

이대로 시작할까요? (y/n/수정)
```

**⛔ STOP: 위 요약을 표시한 뒤 반드시 멈춘다. 사용자 응답이 오기 전까지 Phase F를 절대 실행하지 않는다.**

사용자가 답변하면:
- `y`, `네`, `응`, `ㅇ`, `시작`, `확인`, `좋아` 등 긍정 응답 → "최종 컨셉 확인"을 `completed`로 표시하고 Phase F로 진행
- `n`, `아니`, `수정` 등 부정 응답 또는 특정 항목 수정 요청 → 해당 항목 또는 `free_text`를 수정 후 최종 확인 다시 표시하고 멈춘다
- `추가 설명 수정` / `요약 다시 써줘` 등 → `free_text`만 재작성 후 최종 확인 다시 표시하고 멈춘다

---

## Phase F — 파일 저장 및 하네스 실행

TodoWrite로 "컨셉안 생성 (하네스)"를 `in_progress`로 업데이트한다.

사용자에게 아래 메시지를 표시한다:
```
컨셉안 생성을 시작합니다. 완료까지 10~20분 소요될 수 있습니다.
```

1. Phase E에서 확정된 `free_text`를 포함해 수집된 모든 필드를 `user_input.json`으로 저장한다:

```json
{
  "genre": "<값>",
  "platform": "<값 또는 null>",
  "target_user": "<값 또는 null>",
  "dimension": "<값 또는 null>",
  "reference_games": ["<값>", "..."],
  "play_mode": "<값 또는 null>",
  "combat_mode": "<값 또는 null>",
  "keywords": ["<값>", "..."],
  "free_text": "<값 또는 null>",
  "core_loop": "<값 또는 null>",
  "key_elements": ["<값>", "..."],
  "must_have_elements": ["<값>", "..."]
}
```

2. `pipeline` 스킬을 실행한다:
   - Skill 툴로 `pipeline` 스킬 호출
   - 파이프라인이 단계별 승인 게이트를 거쳐 완료될 때까지 진행

3. 파이프라인이 완료되면 "컨셉안 생성 (하네스)"를 `completed`로 표시한다.

---

## 주의사항

- Phase A, B, C는 최대한 자연스럽게 대화한다. 형식적인 목록 나열 금지.
- Phase B에서 기본 항목을 물을 때 모든 항목을 한 번에 나열하지 말고 대화 흐름에 맞게 묶어서 물어본다.
- Phase C에서 코어 루프/핵심 요소/필수 요소를 물을 때 장르와 앞서 나온 레퍼런스에 맞는 구체적 예시를 든다.
- 리스트 필드(`reference_games`, `keywords`, `key_elements`, `must_have_elements`)에서 빈 입력은 `[]`로 저장한다.
- Phase E에서 `n`을 선택해 Phase D로 돌아갈 경우 "최종 컨셉 확인"은 `in_progress`로 유지한다.
